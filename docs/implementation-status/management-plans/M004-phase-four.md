## 阶段目标与成功标准

在阶段一至三已交付的目标/投递、面试情报和知识/算法/项目/实习四条准备轨道之上，建立规则优先、证据可解释、由页面主动触发的准备评估与任务建议；提供覆盖 MVP 业务事实和必要关系的 Markdown/JSON 导出；完成跨模块逻辑与文档生命周期收口，形成 M004 正式交接。

阶段成功必须同时满足：

1. 目标岗位、结构化情报、四轨道用户状态/事实/版本能够进入可复现的准备优先级链路；投递阶段仅在临近面试时形成有界弱信号。

3. 每日、每周、面试前建议只由用户在页面主动触发；不存在面向用户的定时生成、后台调度或推送。
4. Markdown/JSON 导出覆盖目标、投递、情报、四轨道用户修订、版本/确认状态、证据及必要关联，并明确事实、草稿、情报信号和未证实能力的边界。
5. 所有开发任务完成编码后的逻辑检查并如实记录未执行项；本阶段不新增、要求或执行测试、迁移验证、API/数据库运行态验证、页面行为/浏览器验收或 `npm run build`。
6. 稳定工程事实、状态、索引、归档盘点和正式交接按 `DOCUMENT_LIFECYCLE.md` 收口；阶段只交回项目大总管验收，不自行标记项目完成。
