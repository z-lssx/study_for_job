## 阶段目标与用户价值

把公开且无需登录的面经来源、用户手动提交的链接或正文，转成可追溯、可检索、可统计的面试需求情报。阶段完成后，重复输入和 Worker 重放不产生重复业务事实；失败可诊断并能通过补正文降级；结构化题目、检索结果和频率计数均能回到原始文档与证据，为阶段三四条准备轨道提供可靠输入。

## 阶段范围

- 公开且无需登录来源的受限适配，以及用户手动提交链接或正文。
- 原始内容、清洗正文、来源、处理状态和失败事实持久化。
- 规范化 URL、内容哈希或等价唯一事实实现幂等去重和 Worker 重放安全。
- 抓取/处理失败分类、脱敏原因、有界重试、手动补正文与重新触发。
- 原文先标注再拆分：文档、轮次、内容块、检索 chunk；区分问题、原作者答案、反馈、追问和过程描述。
- 结构化抽取、规范题归一化、出现记录、证据片段与人工修正边界。
- 结构化过滤、FTS/pg_trgm 和在真实需求成立后引入的 pgvector 语义召回。
- 从原始出现事实聚合频率，并提供文档/证据回链。
- 支撑上述链路的桌面 Web、API、Worker 交互与风险相称验证。

## 明确非范围

- 岗位爬取、登录态内容、绕过访问限制或未经确认许可的采集。
- 面向用户的 Cron、定时采集、定时分析或定时推送；`next_run_at` 仍只用于立即创建、手动重试和失败退避。
- 队列取消、DAG、吞吐自适应等无关基础设施扩张。
- 八股、算法、项目、实习四条准备轨道，以及准备评估、任务建议和 Markdown/JSON 导出。
- 多轮模拟面试、项目/实习深挖、LangGraph Agent 或通用聊天。
- 在没有真实检索数据与质量依据前锁死 embedding 供应方式或引入复杂近似索引。
- M002 不编写业务代码、不读取源码/业务 diff/大段日志，也不亲自执行测试、构建、依赖安装或普通代码审查。

## 能力分解、任务顺序与依赖

共享工作区默认顺序派发；前一任务只有在提交、推送、结构化交接和剩余工作树状态明确后，下一任务才进入开发。若出现可安全隔离的工作区再评估并行，否则不并发修改重叠范围。

### T005：面经原始事实与可恢复入库链路

主要结果：公开 URL 或手动正文进入同一文档处理链，形成来源、原始/清洗正文、稳定状态、URL/内容幂等、失败分类和补正文降级，并提供可人工操作的桌面入口。

依赖：T004 Worker。

完成条件：

- 至少一个明确许可边界内的公开、无需登录来源适配器可用；不支持的来源安全失败且仍可补正文。
- 重复规范化 URL、相同正文和 Worker 重放不产生重复文档事实或不可控副作用。
- 网络、来源限制、解析、校验和未知错误映射为稳定、脱敏、可重试/不可重试分类。
- 用户可提交 URL 或正文、查看处理状态与来源、补正文并重新触发；不引入用户定时参数。
- development/usage 双数据库迁移一致，usage 不注入开发事实。
- 任务工作区、稳定技术实现文档、API/Worker/幂等/失败恢复和页面人工验证完整，提交已推送且工作树状态清楚。

### T006：原文标注、结构化抽取与证据链

主要结果：在 T005 原始事实之上形成版本化、可重放的标注/抽取链，保留轮次、内容块类型、问题、追问和证据位置；原作者答案不被误当成标准答案。

依赖：T005 业务链路已完成；安全/网络延期风险不作为本任务阻塞条件。

完成条件：

- 原文先标注再拆分，轮次、内容块和检索 chunk 均能定位到文档字符区间或等价稳定位置。
- 抽取 run 保存 Schema/prompt/模型或确定性处理版本，失败不会覆盖成功原文；重放不重复创建同一版本事实。
- 问题、原作者答案、反馈、追问和过程描述在数据契约与展示中保持可区分。
- 证据片段能回到原文；无证据字段不被伪造成确定事实。
- 真实远程模型仍不可用时，使用受控 fake/fixture 验证契约并明确质量限制，不以假数据声称真实抽取质量。
- 任务级验证、技术文档、提交推送和结构化交接完整。

### T007：规范题、出现事实、人工修正边界与频率统计

主要结果：把抽取问题归一化为规范题，以不可污染的出现记录作为频率事实源，支持合并/拆分或等价人工修正边界，并把每个计数回链到文档与证据。

依赖：T006。

完成条件：

- 规范题与原始出现记录分离；同一文档/轮次内重复抽取不会重复计数。
- 频率按实际出现记录聚合，能按必要的时间、岗位、公司或轮次过滤，并能下钻具体文档和证据。
- 用户修订只改变个人可用的提炼/映射层，不改写原始出现事实；合并/拆分具有明确、可追溯的规则。
- 归一化不确定时保留候选或待确认状态，不强行合并不同问题。
- 桌面页面可人工核对规范题、出现次数和证据回链。
- 任务级验证、技术文档、提交推送和结构化交接完整。

### T008：混合检索、情报质量验收与阶段收口准备

主要结果：在真实阶段数据和证据链上完成结构化过滤、FTS/pg_trgm 精确召回及满足需求时的语义召回，验证精确术语与不同措辞问题，并给出阶段三可依赖的情报质量边界。

依赖：T007。

完成条件：

- 检索结果保留文档、轮次、内容块和证据来源，结构化过滤与词法检索可用。
- 以阶段真实样本证明不同措辞同义问题的召回需求；只有证据支持时才选择并记录 embedding 供应、维度、版本和重建边界，否则采用可明确解释的降级并记录未满足项。
- 不直接混加不同量纲分数；融合/排序规则可复现，无充分证据时返回明确不足而非伪造结论。
- 形成覆盖重复输入、Worker 重放、失败/补正文、结构化证据、规范题计数、精确与同义检索的风险相称验收结果。
- 给出情报质量结论、已知误差、适用范围和阶段三可依赖/禁止假设边界。
- 页面人工验证、稳定实现文档、提交推送和结构化交接完整。

## 任务派发约束

- 每个开发任务必须先创建 `task-workspaces/TXXX/plan.md`，过程中维护 `implementation.md`，完成后创建 `verification-and-handoff.md`。
- 提示词必须在开头列出最少必要 Skills，并要求开发 Agent 完整读取相应 `SKILL.md`；含前端设计/视觉/信息布局的任务必须绑定 `@frontend-design`，数据库模型、查询和索引任务按需绑定 `@build-web-apps:supabase-postgres-best-practices`，页面人工验证按需绑定对应浏览器测试 Skill。
- 开发 Agent 自行执行风险相称的迁移、API、Worker、幂等、失败恢复、检索质量和页面人工验证；未经用户许可不得运行 `npm run build`，页面默认人工验证且不写访问脚本。
- 只有任务完整完成、验证通过、提交范围清晰且敏感信息检查通过时，开发 Agent 才可显式暂存本任务范围、提交并推送；不得全量暂存或混入运行产物、临时文件、秘密和其他任务改动。
- M002 只消费开发 Agent 的结构化摘要、自验证结果和任务交接文档；摘要不足时续发给原任务，不读取源码补齐。
- 验证默认采用开发 Agent 自测加改动相关单测/冒烟；仅认证/外网抓取/SSRF、迁移与数据模型、并发队列/Worker、密钥处理、跨模块大重构、验证明显不足或用户明确要求时触发独立审查。审查或修复回送只做受影响边界测试与最小回归，不重复执行全套测试、全量视觉验收或无关诊断，除非核心路径或回归证据确实需要。
- T008 收口判断：未执行 API、数据库/迁移、页面行为验证不单独阻塞退出条件 7；同义/语义召回按用户确认的延期边界不阻塞本阶段，退出条件 6 按当前阶段范围满足，但继续记录 `unproven` 限制并留给后续能力。

## 风险触发审查条件

默认不为每个增量固定追加独立审查。只有出现以下任一条件时，才在当前任务后插入独立审查或要求原任务补证：

- 破坏性或不可逆数据迁移、生产/usage 数据安全风险。
- 抓取许可、安全、权限、凭据或来源限制边界不清。
- 跨模块大范围重构、重大架构变更或引入新的长期基础设施。
- Worker 至少一次重放无法证明业务幂等，或错误分类可能泄露原文/凭据/内部异常。
- 频率统计可能被用户修订污染，或计数无法回链原始出现证据。
- embedding/检索实现锁定供应方式但没有真实数据质量依据。
- 结构化摘要与状态/技术文档矛盾，或迁移、API、Worker、页面、检索质量验证明显不足。
- 用户明确要求独立审查。

## 阶段退出与交接条件

在用户确认的“业务优先、风险后补”节奏下，M002 停止扩展并把阶段标记为待验收时，必须同时给出业务退出结论与延期风险清单；不得把延期安全问题伪称为已修复：

1. 公开来源或手动正文可进入同一可追溯处理链，始终保留手动正文降级。
2. 重复 URL、相同内容和 Worker 重放不产生重复业务事实或不可控副作用。
3. 失败具有稳定状态、可重试分类和脱敏原因，补正文/重新触发路径可用。
4. 结构化题目、轮次、追问和证据来源明确，用户修订不污染原始频率事实。
5. 题目归一化与频率统计基于出现记录，计数能回到具体文档和证据。
6. 检索覆盖精确术语和不同措辞的同义问题并保留来源；证据不足时不伪造结论。
7. 汇总所有任务的风险相称验证，形成明确情报质量结论和阶段三可依赖边界。
8. 按 `DOCUMENT_LIFECYCLE.md` 完成事实提炼、去重、归档、索引修复、正式阶段交接、治理文档提交与推送，记录 SHA 和剩余工作树状态。

阶段交接必须主动返回来源项目大总管，包含逐条退出条件、任务 Thread ID/SHA/推送状态、验证和情报质量结论、稳定事实源、遗留风险、阶段三可依赖/禁止假设以及工作树状态。若来源大总管不可用，只标记待验收并要求用户恢复同一大总管，不创建新的管理权威。
