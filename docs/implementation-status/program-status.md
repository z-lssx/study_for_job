## 当前任务目标基线

阶段五以 `docs/design/frontend-redesign.md` 为唯一正式设计输入，在不改变现有业务事实和可信边界的前提下，将全部现有 MVP 页面统一重设计为“今日重点首页 + 独立投递页 + 可收起左侧工作台导航”的沉静桌面工作台。深层内容使用真实前端路由，次要信息通过折叠、抽屉、弹窗和短提示渐进披露，四条准备轨道按各自真实任务分别设计。允许为明确页面需求同步补齐必要后端 API，但必须优先复用现有能力，并保持 PostgreSQL 唯一事实源。

用户已明确本轮不设阶段总管，由一个独立实现对话直接完成；该对话可以在内部使用子 Agent，但不得创建新的用户侧开发对话或管理角色。所有视觉实现必须绑定 `frontend-design`。本轮只做逻辑检查，不运行测试或构建；完成后仍由项目大总管验收，且用户确认最终收口前不得标记“项目完成”。

## 跨阶段风险与未决事项

- Worker 是至少一次语义，面经处理器必须实现业务幂等。
- 抓取仅限公开、无需登录内容，并始终保留手动正文入口。
- embedding 方案延后到检索需求明确时决定。
- 真实 DeepSeek/SophNet 模型标识和远程调用仍未验证，但不阻塞原文与状态链路。
- 用户已确认同义/语义召回延期；embedding/pgvector 与真实语义质量评估不阻塞阶段二或阶段三主要功能开发。
- 用户最新最高优先级规则要求后续编码不安排测试相关内容，编码完成后只做逻辑检查；未执行迁移、API、数据库、页面和构建验证仍须如实记录，不得伪造通过结论。
- 阶段四的策略必须规则优先、证据可解释，不读取全量正文制造成本或幻觉，不把情报频率、投递阶段或 AI 草稿误写成用户事实或统一评分。
- 来源许可、真实模型验证和 embedding 供应方式仍属于后续阶段内需受边界约束的实现事项。
- MVP 的准备评估、任务建议、Markdown/JSON 导出和跨模块验收统一进入阶段四，避免在四条轨道尚未稳定时提前整合。
- 多轮 Agent 必须继续位于 MVP 后，不能借随机抽题或准备评估扩入 MVP。
- 本轮前端重设计不得复制情报证据、改变用户事实或增加第二事实源。可按设计简报先盘点后补齐必要后端 API；不得按 React 组件粒度拆接口，不得借 UI 调整扩张业务能力。若必须修改数据库结构，需在实现交接中单独说明理由、影响与未验证边界。
- 页面替换不保留旧版兼容、双版本、功能开关或迁移阶段；但必须保持现有 MVP 功能和数据流边界。
- 阶段五未做运行态和视觉验收，因此真实页面兼容性及 1024×768、1440×900 最终视觉效果仍属于已知未验证边界；按用户规则不要求本轮补做。
