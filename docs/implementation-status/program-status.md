## 跨阶段风险与未决事项

- Worker 是至少一次语义，面经处理器必须实现业务幂等。
- 抓取仅限公开、无需登录内容，并始终保留手动正文入口。
- embedding 方案延后到检索需求明确时决定。
- 真实 DeepSeek/SophNet 模型标识和远程调用仍未验证，但不阻塞原文与状态链路。
- 阶段三开始前必须验证情报数据质量，避免准备轨道建立在不可追溯或低质量抽取上。
- 当前需要用户确认同义召回边界：继续由 M002 补齐证据，或明确接受 `unproven` 为延期风险并调整阶段退出结论。
- 用户已确认后续业务开发优先，不默认补做 API、数据库/迁移和页面行为验证；未执行项仍必须如实记录。
- 来源许可、真实模型验证和 embedding 供应方式仍属于后续阶段内需受边界约束的实现事项。
- MVP 的准备评估、任务建议、Markdown/JSON 导出和跨模块验收统一进入阶段四，避免在四条轨道尚未稳定时提前整合。
- 多轮 Agent 必须继续位于 MVP 后，不能借随机抽题或准备评估扩入 MVP。

- 大总管状态只使用：`未启动 | 活跃 | 暂停 | 项目完成`。
- 宏观阶段状态只使用：`未开始 | 准备启动 | 进行中 | 待验收 | 已完成 | 阻塞 | MVP 后`。
- 同一时间最多记录一个活跃阶段总管；创建成功后必须写入 Thread/session ID。
- 阶段未验收前不得清除当前阶段或创建下一阶段总管。
- 阶段验收后记录交接文档、提交证据和剩余风险，再更新路线图。
- 上下文或事实冲突影响判断时写入“暂停”和恢复检查点，不创建第二个大总管逻辑身份。
- 不把启动提示词、对话记忆或未验证计划写成完成事实。
