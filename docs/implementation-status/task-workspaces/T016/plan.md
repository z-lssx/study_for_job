# T016 实施计划：MVP Markdown/JSON 事实关系导出

更新时间：2026-08-06

## 单一目标

提供由用户显式触发的同步只读快照导出：以同一规范关系模型生成 JSON 与 Markdown，覆盖目标、投递、结构化情报、知识/算法/项目/实习四轨道的用户事实、修订、版本/确认/材料状态、证据及必要关系，并保留可复现与不外推能力的边界。

## 成功标准

- 请求显式携带 `as_of_date` 与格式；页面打开、格式/日期变化不自动生成。
- 后端单次只读快照聚合底层业务事实；Markdown 与 JSON 只做同源投影。
- 稳定 ID、关系 ID、稳定排序、schema/export version、显式触发、计数、warnings/limitations 和 fingerprint 完整保留。
- confirmed、draft、ai_draft 来源、表达版本、材料、情报需求信号、无证据与未证实能力明确分层。
- 证据只返回已有引用和有界片段，不读取或输出全量面经正文。
- 页面提供格式、可见日期、主动生成、摘要和下载动作，以及首次/加载/空/错误状态。
- 只修改 T016 直接相关代码、稳定实现文档/索引与本工作区。

## 实施步骤与逻辑检查

1. 读取模型、迁移、既有 API/服务、前端壳层和风格实现，建立字段/关系清单；逻辑检查事实源与状态语义不冲突。
2. 实现规范导出快照、稳定排序/指纹及 JSON/Markdown 投影；逻辑检查两格式同源、集合/关系覆盖和正文边界。
3. 注册同步只读 API；逻辑检查请求只含显式日期/格式且无持久化、任务、调度或推送。
4. 实现导出页面、client/type、导航与局部样式；逻辑检查仅提交触发、下载动作、空错态与既有视觉一致。
5. 更新唯一稳定导出实现文档、索引和 T016 交接；逻辑检查去重与链接职责。
6. 仅做源码/契约逻辑检查和 Git 提交控制检查，限定暂存 T016 文件，提交并正式尝试推送一次。

## 最高优先级验证边界

不编写或执行任何测试、测试脚本、静态语法/类型/lint 检查、迁移验证、API/数据库运行态验证、页面/浏览器/截图验收、`npm run build`、`npm run check` 或其他构建。只记录逻辑检查结论；Git scoped diff、敏感信息和工作树检查只用于提交控制。

## 非范围

不修改 T014 规则或 T015 策略数据流；不导出 assessment 代替底层事实；不实现自动备份/恢复、定时任务、Worker、推送、RAG、semantic recall、embedding/pgvector、Agent、在线判题、LeetCode 同步、登录/多用户、岗位爬取、移动端专属能力、T005 延期风险修复或全站重设计。
