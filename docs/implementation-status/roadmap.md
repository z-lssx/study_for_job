# 高层路线图

更新时间：2026-08-08

本路线图只描述能够形成稳定用户能力的宏观阶段。阶段内普通开发任务、任务数量和技术细节由唯一活跃阶段总管维护。

## 阶段一：数据底座与投递闭环（已完成）

- 用户价值：形成可本地运行的基础应用和“目标岗位/公司 → 投递记录 → 看板维护”闭环。
- 进入条件：初始项目范围已确认。
- 范围：PostgreSQL 唯一事实源、迁移、目标画像、投递记录、桌面看板、AI Gateway、Prompt/Token 账本、PostgreSQL 队列与独立 Worker。
- 非范围：面经采集分析、准备轨道、策略报告和 Agent。
- 退出条件：基础链路、双数据库隔离、AI 调用边界和至少一次任务执行机制已验证并完成阶段交接。
- 完成证据：`handoffs/M001-phase-one-handoff.md`，阶段收口提交 `4880c80f067e8266e10ed4dce04c58cc515e56da`。

## 阶段二：面试情报闭环（已完成）

- 用户价值：把公开面经或用户正文转成可追溯、可检索、可统计的面试需求情报。
- 进入条件：阶段一已验收；数据库、AI Gateway 和 Worker 边界稳定可用。
- 范围：公开且无需登录的来源适配、手动链接/正文入口、原文持久化、URL/内容幂等、失败与补正文降级、结构化抽取、题目归一化、证据回链、结构化过滤与可解释词法/相似候选检索、频率统计。
- 非范围：岗位爬取、面向用户的定时采集、准备轨道、准备评估、多轮 Agent，以及无来源许可的抓取绕过。
- 退出条件：重复 URL/内容不产生重复事实；处理失败可诊断并可补正文重试；规范题、频率统计和现有检索结果均能回链原始证据；语义召回按用户确认延期为后续能力，继续明确标记为 `unproven` 且不伪造成已覆盖；阶段总管已给出情报质量结论、稳定实现文档和正式交接，且交接已验收。
- 主要风险：Worker 至少一次语义要求业务幂等；来源许可与页面变化；模型抽取质量；embedding 供应方式不得在没有真实检索需求时提前锁死。
- 阶段文档：阶段总管维护 `management-plans/`、`current.md`、`queue.md`，完成后提交阶段二 `handoffs/` 和情报/检索稳定实现文档。

## 阶段三：四条准备轨道（已完成）

- 用户价值：把面试需求情报转成用户可维护、可复习的知识、算法和经历准备资产。
- 进入条件：阶段二情报质量满足退出条件，规范题与证据引用可作为可靠输入。
- 范围：八股题目/知识点与轻量掌握状态、外部算法题单与错题复盘、项目/实习证据包与版本管理、轻量随机单题练习；结合新页面开发完成一次现有桌面工作台的沉静化视觉与信息层级优化。
- 非范围：在线判题、LeetCode 账号同步、百科式标准答案、事实编造、统一伪评分、跨轨道策略报告和多轮模拟面试。
- 退出条件：四条轨道均能独立维护真实状态；情报信号能以适合各轨道的方式关联；用户修订不会被 AI 覆盖；随机练习保持轻量单题边界；核心准备信息优先、次要信息可通过折叠/抽屉/弹窗按需展开，页面分区与纵向节奏适合持续专注使用。
- 主要风险：四条轨道数据模型被错误统一；AI 草稿污染用户事实；情报信号被误当成单值评分；视觉优化扩大为无边界重写或影响既有数据流。
- 阶段文档：阶段总管维护阶段计划、状态和交接，并提炼四类准备资产的稳定实现事实。

## 阶段四：策略闭环、导出与 MVP 收口（已完成，等待用户确认 MVP 收口）

- 用户价值：综合面经需求和个人掌握状态，按需得到有来源的准备评估与任务建议，并能导出个人数据。
- 进入条件：四条准备轨道都能提供可靠状态和证据，阶段一投递信息仍只作为临近面试的弱信号。
- 范围：规则优先的准备优先级、页面主动触发的准备评估报告、每日/每周/面试前任务建议、来源引用、Markdown/JSON 导出，以及 MVP 跨模块人工验收和文档收口。
- 非范围：面向用户的定时生成或推送、通用聊天、重型备份恢复、多轮模拟面试和其他 LangGraph Agent。
- 退出条件：主链路从目标与情报进入准备资产和策略报告可用；建议可解释且有证据；Markdown/JSON 导出覆盖 MVP 业务事实；所有 MVP 阶段完成交接。只有用户确认收口后，项目大总管才能标记“项目完成”。
- 主要风险：策略层读取全量正文导致成本和幻觉；投递阶段权重过强；导出遗漏用户修订或证据关系；把测试性整合扩成后续 Agent。
- 阶段文档：阶段总管维护阶段计划、状态、MVP 验收证据和正式交接；项目大总管仅维护最终宏观验收结论。

## 阶段五：桌面工作台整版重设计（进行中）

- 用户价值：把现有 MVP 能力重新组织为安静、清晰、适合长期专注使用的秋招准备工作台，让用户进入应用后能快速看到最值得推进的事项。
- 进入条件：阶段一至四已经验收；用户已确认 `docs/design/frontend-redesign.md` 并明确授权本轮不设阶段总管、直接创建一个实现对话。
- 范围：统一应用壳层和设计变量、今日重点首页、独立投递页、可收起左侧导航、真实前端路由与可恢复 URL、全部现有 MVP 页面的视觉与交互重设计、按真实任务分别设计四条准备轨道、加载/空/错/成功/未保存等必要 UI 状态；在先盘点和优先复用现有接口后，同步补齐有明确页面消费方的必要后端 API。
- 非范围：改变现有业务事实边界、复制数据或新增第二事实源、按 React 组件粒度拆 API、无明确 UI 消费方的后端改造、语义召回/embedding/pgvector/RAG/Agent、移动端专属能力、旧版兼容、双版本、功能开关、测试和构建。
- 退出条件：`docs/design/frontend-redesign.md` 的成功标准在代码结构和交互逻辑层面全部覆盖；全部现有 MVP 功能和事实边界保留；实现对话给出结构化摘要、提交与推送事实、未执行验证和遗留风险；项目大总管完成验收。
- 实施治理：按用户一次性明确授权，本阶段不设阶段总管；由项目大总管创建唯一实现对话，该对话必须使用 `frontend-design`，可在内部使用子 Agent 分工，但不再创建新的用户侧对话。编码后只做逻辑检查，不运行测试或构建。
- 主要风险：表面视觉替换掩盖原功能丢失；路由重组破坏现有状态；过度渐进披露降低可发现性；API 调整扩大到无关后端或事实模型；新旧样式混杂。

## 阶段六：受限 Agent 场景（MVP 后）

- 用户价值：在用户决定继续后提供可暂停恢复的多轮模拟面试和项目/实习深挖。
- 进入条件：阶段五完成验收、用户完成最终收口并明确决定继续，且情报、准备资产和策略层均有稳定事实源。
- 范围：受限工具白名单、LangGraph PostgreSQL checkpoint、预算与评估集、多轮模拟面试、项目/实习深挖。
- 非范围：通用聊天型 Agent、未经确认的写操作、用 checkpoint 替代业务事实源。
- 退出条件：由用户在 MVP 收口后另行确认，不作为当前 MVP 完成条件。

## 跨阶段约束

- 已确认产品决策优先于本路线图；只允许调整尚未开始的宏观阶段。
- DeepSeek V4 已确认作为大模型服务；具体档位、调用参数和 embedding 供应方式由相应实现任务按真实需求决定并记录。
- MVP 本地优先，保持模型、存储和部署边界可替换。
- 不实现登录/多用户、定时推送、自动岗位爬取、在线判题或通用聊天型智能体。
- 桌面 Web 是唯一正式支持端；只保留基础响应式，不规划移动端专属能力。
- 普通业务页面不默认使用 ImageGen，只有明确需要位图资产时才调用。
- 前端设计或视觉实现任务必须绑定 `@frontend-design`；阶段五按用户明确授权由直接实现对话承担该绑定。
- 语义召回、embedding/pgvector 和相应质量评估延期，不阻塞阶段三；后续只有真实查询样本证明需要时再进入独立能力任务。
- 用户最新最高优先级规则要求编码任务不安排测试内容，完成后只做逻辑检查并如实记录未执行项；不得伪造测试或运行态通过。
