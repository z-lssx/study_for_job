# 高层路线图

更新时间：2026-08-02

## 当前阶段：阶段一·数据底座与投递闭环

目标是先建立可本地运行的前后端分离模块化单体，并打通“目标岗位/公司 → 投递记录 → 看板查看与维护”的最小闭环。该阶段只验证业务事实源、基础 API、页面交互和本地运行方式，不引入面经抓取或智能体流程。

阶段目标：

- PostgreSQL 作为唯一业务事实源，完成迁移和基础领域表。
- 目标画像与投递记录支持用户主动创建、编辑、查看。
- 前端能够消费 API，展示投递看板和关键状态。
- 预留 AI Gateway、任务队列和后续情报层的清晰边界，但不在首条链路中实现。
- 形成可重复的本地启动和人工验证路径。

## 阶段二：面试情报闭环

依赖阶段一的数据访问和任务执行边界。依次实现公开来源适配、原文持久化与去重、结构化抽取、题目归一化、证据回链、混合检索和频率统计；始终保留用户手动提交正文的降级入口。

## 阶段三：四条准备轨道

在情报质量可用后，依次接入八股知识卡与掌握度、算法题单与复盘、项目/实习证据包与版本管理、随机抽题练习，以及页面主动触发的准备评估报告。

## 阶段四：受限 Agent 场景

最后实现多轮模拟面试、项目/实习深挖等需要状态恢复和动态决策的流程，使用 LangGraph checkpoint；该阶段不改变随机抽题的轻量单题定位。

## 跨阶段约束

- DeepSeek V4 已确认作为大模型服务；具体档位、调用参数和 embedding 供应方式由实现任务自主决定并记录。
- MVP 本地优先，保持模型、存储和部署边界可替换。
- 不实现登录/多用户、定时推送、自动岗位爬取、在线判题或通用聊天型智能体。
- 桌面 Web 是唯一正式支持端；只保留基础响应式，不规划移动端专属能力。
- 普通业务页面不默认使用 ImageGen，只有明确需要位图资产时才调用。
- 每个开发任务自行完成与风险相称的验证；独立测试/审查只在高风险、结论矛盾、验证不足或用户明确要求时派发。
