# 桌面工作台壳层与真实路由

状态：阶段五已完成代码实现与静态逻辑检查（2026-08-08），等待项目大总管验收。

## 解决的问题

前端从组件内 `activeView` 切换和投递横向五列看板，重组为“今日重点首页 + 独立投递页 + 可收起左侧工作台导航”。全部现有 MVP 页面使用同一套暖灰、米白、深墨与低饱和墨绿设计变量，但知识、算法、项目和实习仍按各自任务组织，不共享伪统一的数据模型或评分。

## 壳层与路由

`src/app/router.jsx` 基于浏览器 History API 维护 URL、前进后退和刷新恢复，不新增路由依赖。`src/app/App.jsx` 只负责路由分发和既有数据依赖注入；`AppShell` 负责可收起侧栏、目标画像上下文、数据环境提示和最大 1360px 的桌面内容区。

稳定入口包括：

- `/`、`/profile`、`/applications`、`/planning`、`/exports`、`/settings/ai`；
- `/intelligence`、`/intelligence/:id`、`/intelligence/search`、`/intelligence/questions[/:id]`；
- `/knowledge[/:id]`、`/algorithms[/:id]`；
- `/projects`、`/projects/new`、`/projects/:id`、`/projects/:id/edit`；
- `/internships`、`/internships/new`、`/internships/:id`、`/internships/:id/edit`。

侧栏收起状态只属于界面偏好，可保存在浏览器 `localStorage`；业务事实、详情和策略结果不写入浏览器持久化。重要详情刷新后通过既有按 ID API 重新读取 PostgreSQL 事实。投递详情保持列表上下文中的抽屉职责，深链通过按 ID GET 恢复，阶段推进使用真正的局部 PATCH；复杂情报和四轨道内容进入独立 URL。项目与实习的新建、长编辑分别使用独立 URL，只读详情不暴露修改表单。

## 今日重点与策略事实边界

当前 `POST /api/planning/assessments` 是用户显式触发的同步只读计算，不持久化报告，也没有 `generated_at`、latest 或详情读取接口。首页因此不会自动 POST、缓存页面内存、复用任务队列或用投递日期伪造最近策略；它稳定显示“尚无可恢复策略快照”，引导用户进入策略页主动生成。

首页只把今天及未来、非 `closed` 投递的 `key_date` 当作通用临近节点，并从四轨道现有列表接口读取真实数量。`key_date` 不被解释为面试日期，轨道数量不被解释为能力分。未来若需要恢复最近策略，必须在单独授权下增加属于 planning 领域的 PostgreSQL 持久化结构，不能借用 `jobs.result_summary` 或浏览器存储。

## 页面职责与交互边界

- 目标画像使用独立页面和显式编辑模式；投递新建使用短弹窗，列表详情使用抽屉。
- 情报提交使用短弹窗；来源、处理恢复、抽取块和人工标注位于单条详情页；检索与规范题为二级页面。
- 知识详情承载口述、复习和证据；算法详情承载外部练习入口、状态、卡点与复盘。算法表只有累计次数和最近时间，页面不伪造逐次练习历史。
- 项目与实习列表只提供资产包入口；详情分别组织事实、证据、表达/STAR 版本、材料和情报关联。确认版本的不可覆盖边界保持不变。
- 策略页只在显式提交时生成；导出页只在显式提交时生成和下载；AI 设置把 Prompt、运行诊断和默认折叠的 token 账本分区。

主要编辑表单在页面内导航和浏览器离开时接入未保存提醒。侧栏展开/收起、页面切换、抽屉、弹窗和折叠仅使用短时过渡；关键操作不依赖 hover，focus 状态保持可见。

## API 与数据结构影响

本轮没有修改后端、迁移或数据库 schema。新增前端封装只复用既有能力：知识、算法、项目和实习按 ID GET，以及知识 evidence 的既有 POST/DELETE；投递阶段使用既有 PATCH。列表筛选、阶段概要和轨道摘要在当前单用户本地数据量下由客户端派生，没有新增组件粒度摘要 API。

## 逻辑检查与未验证边界

实现后只检查了路由分发、详情 ID 传递、导入引用、API endpoint/HTTP method、局部 PATCH、未保存提醒、旧 `activeView` 移除、CSS 变量和桌面断点关系，并执行限定范围 `git diff --check`。按项目规则，没有执行测试、构建、lint、类型检查、迁移、API/数据库运行、页面或浏览器验证；因此运行时兼容、真实数据规模和 1024/1440 视口的最终视觉效果仍需在后续获得授权时人工确认，不能宣称已经运行通过。
