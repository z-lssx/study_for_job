# 技术架构文档规则

- 本目录是项目技术设计和实现复盘的长期工程事实区，可按主题持续拆分文件夹和文件。
- `overview.md` 维护仍然有效的系统级架构；`decisions/` 记录有实际影响的技术取舍；`implementation/` 记录已经实现并验证的机制。
- 完成功能后，只在确实产生非显而易见的架构、数据流、AI/检索、可靠性或工程取舍时增量更新相关材料。
- 重要工程决定应按需要记录：解决的问题、最终选择、关键不变量、会改变行为的精确默认参数或公式、替代方案、代价、验证证据和演进触发条件。
- 普通 CRUD、样式调整、机械重构和不影响系统行为的常量不需要记录；只写已实现并验证的事实，不复制大段代码，不把建议写成当前实现。
