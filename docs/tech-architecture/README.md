# 技术架构文档

本目录把 Agent 工程上下文与用户面试材料分开维护。

## Agent 工程事实入口

- [总体技术架构](overview.md)：系统级结构和长期边界。
- [关键技术决策](decisions/README.md)：重要取舍、替代方案和演进条件。
- [模块实现记录](implementation/README.md)：已实现机制、精确参数和验证事实。

开发 Agent 默认只读取与任务相关的上述事实层。`overview.md` 不记录每次开发过程；`decisions/` 只记录会影响后续实现的选择；`implementation/` 只记录已经落地并验证的机制。

## 用户面试准备入口

- [技术面试材料](interview/README.md)：面向用户组织项目讲解、追问、回答结构和量化证据。

`interview/` 是派生表达层，不是 Agent 的实现事实源。材料必须链接相应决策、实现和验证记录；发生冲突时以工程事实层为准。普通开发 Agent 不因阅读本索引而默认加载面试材料。

## 维护原则

- 先维护工程事实，再提炼面试表达。
- 工程文档强调准确、可执行和可验证；面试文档强调问题、取舍、证据、局限和演进。
- 不把普通常量全部写入文档；只有影响行为、可靠性边界或重要技术解释的参数才进入稳定事实层。
- 不因格式调整重写已有的有效决策。
