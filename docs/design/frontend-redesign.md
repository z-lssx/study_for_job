# 前端整版重设计方案

> 状态：用户已于 2026-08-08 明确确认“达到共同理解”；这是可交接的设计简报，不是实施完成记录。
> 来源项目大总管 Thread ID：`019fc0d0-5d8a-7e80-b5c5-93de2eb2bd53`

## 设计北极星与用户场景

- 设计北极星：让用户打开应用后迅速判断“现在最值得推进什么”，并能安静、持续地完成秋招准备，而不是先阅读品牌宣言或管理大量视觉噪声。
- 核心场景是个人长期使用的桌面 Web 工作台；用户会在情报、策略、投递和四条准备轨道之间频繁切换，也会进入单条内容进行较长时间的阅读、修订和复盘。
- 信息设计优先保护事实可信、证据回链和用户修订，不以视觉整齐为理由破坏不同模块的业务差异。
- 体验记忆点来自安静温暖的研究工作台气质、清晰的下一步行动和克制灵动的空间交互，而不是装饰性背景或夸张动效。

## 本次设计讨论的权限与边界

- 当前对话只负责形成整版前端重设计方案。
- 本设计讨论未修改项目代码、未创建开发任务、未提交 Git、未运行测试或构建。
- 任何最终实现必须使用 `frontend-design`，但本对话不执行实现。

## 已确认决策

### 1. 整体应用结构

- 采用“今日重点首页 + 独立投递页 + 可收起左侧工作台导航”。
- 当前以投递看板为首页的结构被替换；投递记录恢复为独立工作流页面。
- 页面顶部只承担当前页面标题、上下文状态和主要操作。

### 2. 今日重点首页

- 首页采用行动优先结构。
- 首要区域突出一个明确的下一步行动。
- 下方仅展示少量候选行动、临近节点和准备轨道摘要。
- 建议显示生成时间，由用户主动重新评估；不伪装成定时或实时生成。
- 无建议时引导补充事实或主动生成，不编造任务填满页面。

### 3. 视觉方向

- 采用“安静、温暖的研究工作台”。
- 暖灰背景、米白内容面、深墨正文、低饱和墨绿主强调色。
- 移除全局网格、条纹、颗粒、渐变和装饰性英文编号。
- 中文无衬线字体承担正文；衬线字体只少量用于标题。
- 禁止海报式巨型文案，以留白、字号、字重和细分隔线建立层级。
- 阴影主要用于抽屉、弹窗等浮层。

### 4. 动效

- 交互可以灵动、高级，但不能喧宾夺主。
- 动效主要用于导航收展、页面切换、抽屉进出、折叠展开和状态反馈。
- hover 只做轻微抬升、边框或底色变化，避免大幅移动和重排。
- 不新增应用内“减少动态效果”设置；这不属于当前 MVP。
- 禁止循环动画、视差滚动、自定义光标和大面积跟随效果。

### 5. 信息层级与渐进披露

- 全站遵循“概览 -> 操作 -> 详情”的信息层级。
- 页面正文只保留当前模块的主要状态和首要操作。
- 筛选、来源证据、历史版本等辅助内容可折叠，但必须有明显入口。
- 深层内容默认进入独立页面，而不是默认塞入抽屉。
- 抽屉只用于不离开上下文的快速预览、简单编辑或状态推进。
- 弹窗只用于新建、确认、少字段设置等短任务。

### 6. 页面层级与路由

- 面经详情、知识题详情、项目/实习证据包、完整评估报告等复杂内容使用独立详情页。
- 二级页面左上角提供返回按钮和简洁面包屑。
- 浏览器前进、后退和刷新后应保持当前页面；重要详情拥有可直接访问的地址。
- 需要多步骤操作、长时间阅读或继续深入的内容不得塞入抽屉或弹窗。

### 7. 页面高度与滚动

- 不强制每个模块占满一屏，也不使用固定 `100vh` 堆叠页面。
- 首屏应形成完整的主要工作单元，长内容自然滚动。
- 禁止无层级的连续内容平铺。
- 仅一级工作段采用轻度接近式吸附，倾向 `scroll-snap-type: y proximity`。
- 卡片、表单、折叠内容和二级模块不参与吸附。
- “进入下一重点”仅在任务流存在明确顺序时使用，不作为固定装饰。

### 8. 字体与信息密度

- 采用舒适密度，不以一屏塞入最多信息为目标。
- 正文默认约 16px，行高约 1.6-1.7。
- 导航和常规按钮约 15px。
- 表单标签、卡片摘要和辅助操作不低于 14px。
- 仅日期、编号、来源等非关键信息可用 12-13px。
- 页面标题约 28-32px，模块标题 20-24px，卡片标题 16-18px。
- 通过页面层级、折叠、筛选等降低密度，不通过缩小字体解决。

### 9. hover、点击与键盘聚焦

- 点击完成任务，hover 只增强理解。
- 关键入口、状态和主要操作始终可见，不能只在 hover 后出现。
- hover 提示在键盘 focus 时也必须可用。
- 卡片整体可点击时，同时支持 `Enter` / `Space`。
- Tooltip 只解释图标或短术语；多行信息或交互使用可点击 Popover、页面、抽屉或弹窗。
- Popover 和浮层支持再次点击、点击外部或 `Esc` 关闭。

### 10. 投递记录页

- 用“阶段概要 + 舒适列表 + 详情抽屉”替代当前横向五列看板。
- 顶部阶段条展示五个阶段的数量与分布，并可筛选列表。
- 列表重点展示公司、岗位、关键日期和下一步行动。
- 点击记录可快速打开详情抽屉，在其中编辑或推进阶段。

### 11. 左侧导航

- 顶部固定入口：今日重点。
- 当前目标画像以简洁上下文卡展示，点击进入独立画像页面。
- 工作流：面试情报、准备策略、投递记录。
- 准备轨道：知识、算法、项目、实习。
- 工具：导出、AI 设置。
- 底部显示开发/使用数据环境和导航收起按钮。
- 展开时显示图标和约 15px 文字；收起后保留图标，并通过 hover 与 focus 显示名称。

### 12. 重设计覆盖与实施边界

- 所有现有 MVP 页面纳入统一重设计，包括列表、详情、表单、空状态和错误状态。
- 不增加新业务模块、不扩展移动端专属能力。
- 项目尚未投入使用，不需要旧版兼容、双版本并存、功能开关或迁移方案。
- 后续可直接按模块进行设计与开发，完成一个模块就替换其旧结构。
- UI 方案可以推动必要的后端开发，不要求前端被现有接口形状锁死。
- 实现时优先复用已有接口；只有现有接口无法合理支撑页面层级、摘要、筛选、详情加载或操作反馈时，才新增有明确 UI 消费方的接口。
- 新接口必须服务已确认的 MVP 用户任务，禁止按组件随意拆接口或借 UI 重设计扩张业务范围。

### 13. 四条准备轨道

- 统一设计系统，但按真实任务分别设计页面，不强套同一种卡片模板。
- 知识轨道围绕题目、知识点、口述练习和追问。
- 算法轨道围绕优先题单、外部练习入口、卡点和复盘。
- 项目轨道围绕事实证据包、表达版本和追问树。
- 实习轨道突出职责边界、STAR、量化结果、证据和表达。

### 14. 桌面布局尺寸

- 左侧导航展开宽度约 240px，收起后约 68-72px。
- 主内容区流式伸缩，最大宽度约 1280-1360px并居中显示。
- 常规页面水平留白约 32-48px；长文本详情使用更窄的阅读列。
- 较窄桌面视口下导航默认收起，但仍使用同一套侧栏，不开发移动端专属导航。
- 约 1024px 桌面宽度下仍需保证正文、表单和列表可正常操作，不依赖缩小字体。
- 宽屏优先增加留白或辅助区域，不无限拉长正文和表单。

### 15. 色彩使用原则

- 色彩规范以整站和谐、低干扰和跨页面一致为目标，不为每一种状态机械指定独立颜色。
- 暖灰、米白、深墨和低饱和墨绿构成主要视觉基调，其他颜色按实际状态克制使用。
- 主要操作、选中状态、提示和错误应保持稳定的视觉含义，但允许设计阶段根据整体效果微调。
- 状态不能只依靠颜色表达，必须同时提供文字、图标或形状线索。
- 禁止高饱和色大面积铺满卡片，避免重新形成视觉噪声。

### 16. 表单与编辑模式

- 默认页面保持阅读和浏览状态，不常驻展示大量输入框。
- 简短新建操作使用弹窗；项目、实习等长表单进入独立新建或编辑页。
- 详情页通过明确的“编辑”操作进入编辑状态。
- 长表单使用显式“保存 / 取消”；离开未保存页面时给予提醒，不在当前 MVP 引入复杂自动保存。
- 掌握状态、投递阶段等单字段操作可以直接修改，并立即显示成功或失败反馈。
- 卡片内部不再层层展开多个编辑表单。

### 17. 加载、空状态与操作反馈

- 首次加载使用与最终内容轮廓接近的骨架屏，避免整页跳动。
- 局部刷新只更新对应区域并保留原内容；触发按钮显示进行中状态。
- 保存成功使用短暂、克制的 Toast，同时让被修改的状态立即可见。
- 表单错误显示在对应字段旁；网络或页面级错误使用清晰的页内提示。
- 空状态说明为空的原因，并只提供一个最合理的下一步操作，不使用大幅插画填充。
- 删除、覆盖确认版本等不可逆或高风险操作必须二次确认；普通状态切换不滥用确认弹窗。
- 所有模块使用一致的反馈措辞、图标和位置。

## 核心页面改造清单

### 今日重点

- 作为默认首页，首屏展示唯一首要行动、推荐原因、预计投入、关键日期和建议生成时间。
- 次级区域最多展示少量候选行动、临近节点和四条准备轨道摘要。
- 提供明确的“重新评估”入口；没有评估结果时引导补充事实或主动生成，不编造任务。

### 目标画像

- 从设置弹窗提升为可直接访问的独立页面。
- 默认展示当前目标岗位、地点、重点方向和摘要；通过显式编辑模式修改。
- 作为全局上下文显示在侧栏，但不把画像包装成虚假评分。

### 面试情报

- 首页改为情报台账：状态摘要、提交入口、筛选与原始事实列表，不再连续平铺提交、详情、检索和规范题四个大板块。
- URL 或正文提交属于短任务，可使用集中式提交弹窗或紧凑提交区。
- 单条情报进入独立详情页，承载来源、处理状态、失败恢复、原文预览、抽取块、个人备注和证据链。
- 证据检索与规范题频率作为明确的二级页面或页内一级工作段，保留原文回链、人工合并、拆分和改映射能力。

### 准备策略

- 页面首要操作是主动生成一次规则快照，并清楚展示模式、日期、目标画像和生成时间。
- 最新策略先显示少量可操作建议；排序契约、输入摘要、警告和证据解释按需展开。
- 可持久化的完整策略结果使用独立详情页；当前若结果只存在于页面内存，则先保持当前页内结果区，并由实现阶段判断是否需要后端持久化与详情接口。
- 今日重点只消费真实存在且可稳定读取的策略结果，不制造后台自动规划或定时推送的假象。

### 投递记录

- 使用“阶段概要 + 舒适列表 + 快速详情抽屉”替代横向五列看板。
- 列表展示公司、岗位、阶段、关键日期和下一步行动；阶段概要用于筛选和查看分布。
- 快速编辑与阶段推进可在抽屉完成；复杂内容仍可进入独立详情或编辑页。

### 知识轨道

- 首页围绕待复习题目、知识点入口、掌握状态筛选和随机单题练习组织。
- 创建题卡不再与全部列表长期并排；单条题目进入独立详情页查看口述版本、追问、资料和证据。
- 复习次数、掌握状态和证据数量作为辅助信息，不做虚假单值评分。

### 算法轨道

- 首页围绕优先题单、状态筛选、随机一题和近期复盘组织。
- 单条题目进入详情页，集中展示外部题目链接、状态、卡点、复盘、练习记录和下次复盘信息。
- 练习动作继续发生在外部平台，本产品不增加在线编辑、运行或判题。

### 项目轨道

- 项目列表与单项目资产包分离；新增和长内容编辑使用独立页面。
- 项目详情按事实、证据包、表达版本、追问树和岗位考点关联组织一级工作段。
- 已确认表达版本不可被覆盖；情报频率只解释关联，不能替用户编造经历。

### 实习轨道

- 实习列表与单段经历资产包分离；新增和长内容编辑使用独立页面。
- 详情围绕基本事实、职责边界、STAR、量化结果、材料版本、追问和情报关联组织。
- 事实、表达和面经信号保持清晰边界。

### 导出

- 页面保持单一导出任务：选择范围和格式、生成事实快照、查看摘要与警告、下载文件。
- schema、限制和详细计数默认折叠，避免把技术清单全部铺在主流程中。

### AI 设置

- 移除展示型巨幅标题，明确区分 Prompt 配置、调用与 token 账本、运行状态和诊断。
- Prompt 使用索引加独立编辑区，重要修改显式保存。
- 用量统计和最近 trace 通过筛选与分区呈现，不把所有诊断信息堆在首屏。
- 仍是有限管理端，不扩展成通用聊天入口或重型运营后台。

## 成功标准与禁止回归

- 在约 1024x768 和 1440x900 的桌面视口下，页面不出现整页横向滚动，关键文字不低于已确认字号。
- 首页首屏可直接识别唯一首要行动、生成时间和少量候选行动，不再以巨型口号或投递统计占据中心。
- 每个一级页面首屏形成完整工作单元，不出现下个大模块只露出标题或半张卡片的情况。
- 一级工作段只产生轻度接近式吸附，不阻碍长内容自然滚动。
- 左侧导航、返回按钮、面包屑、浏览器前进后退和页面刷新保持正确层级与当前可持久化详情。
- 所有关键操作无需 hover 即可发现，并可通过键盘聚焦和触发。
- 现有 MVP 功能、领域事实和可信边界全部保留；允许为已确认 UI 任务增加必要后端接口。
- 四条准备轨道视觉一致，但不被强制做成相同页面模板。
- 每个模块具备加载、空状态、错误、成功和未保存提醒等必要状态。
- 全站不再出现全局网格、条纹、颗粒、海报式大标题、普遍小字号或长期新旧样式混搭。
- 完成验收以页面结构、交互逻辑和视觉一致性检查为主，遵循项目“不运行测试或构建”的规则。

## 明确非范围

- 不新增登录、多用户、移动端专属导航、手势、底部栏、PWA、离线同步或原生客户端。
- 不新增在线判题、LeetCode 同步、岗位爬取、通用聊天智能体、面向用户的定时任务或重型运维能力。
- 不为了视觉统一改变情报证据、用户修订、项目/实习事实和 AI 边界。
- 不设计旧版兼容、双版本并存、功能开关或长期迁移方案。
- 不在本设计讨论中实现前端、后端或数据库代码，不创建开发任务，不提交 Git，不运行测试或构建。

## 给项目大总管与未来阶段总管的实现约束

- 最终实现必须绑定 `frontend-design`，先建立统一应用壳层、真实路由层级和基础设计变量，再按模块直接替换旧结构。
- 项目尚未投入使用，不承担旧 UI 兼容成本；模块可以直接按新方案设计与开发。
- UI 需求可以推动必要后端开发，但必须先盘点和复用已有接口。
- 只有现有接口无法合理支撑摘要、筛选、分页、独立详情、局部更新或清晰操作反馈时，才新增有明确页面消费方的接口。
- 禁止按组件机械拆接口、复制已有查询或借重设计扩张 MVP；新增接口必须维护既有领域事实和安全边界。
- 深层内容需要真实路由和可恢复 URL，不能继续只依赖组件内 `activeView` 或临时选中状态模拟多页面。
- 页面、抽屉、弹窗、折叠和 Tooltip 必须遵循本文已确认的职责边界。
- 设计与开发时保持精准修改，不顺手重构无关后端或扩展业务能力。
- 按项目规则，编码完成后只做逻辑检查，不运行测试或构建；对应技术实现事实按 `docs/tech-architecture/AGENTS.md` 补充。

## 需要后端配合评估的具体内容

- 今日重点需要稳定读取“最近一次可用策略结果、生成时间、首要行动、候选行动和临近节点”。先核对现有策略接口与数据是否可复用；如果策略快照当前只存在于前端内存，应由项目大总管安排评估是否增加持久化和读取接口。
- 独立详情页需要刷新后可恢复。先核对面经、知识题、算法题、项目、实习和投递是否已有按 ID 查询接口；缺失时再补充明确的详情接口，不为每个详情子区重复查询。
- 阶段概要、列表筛选、分页和摘要优先由现有列表接口在合理数据量内复用；只有客户端聚合明显不合理或数据量需要时，才增加服务端筛选、分页或摘要能力。
- 掌握状态、投递阶段、复习记录等局部操作优先复用现有 PATCH/动作接口；仅在现有接口要求提交整对象、容易覆盖并发事实时，才增加边界清晰的局部更新接口。
- 情报检索、规范题、证据链和人工修正继续维护既有事实边界，不因页面拆分复制数据或新增另一套事实源。
- 所有新增接口必须有明确页面消费方、稳定领域语义和错误反馈契约，禁止按 React 组件粒度拆接口。
