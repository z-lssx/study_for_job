# 桌面工作台设计规范

状态：当前前端长期设计基线。视觉或交互补丁不得破坏本规范，除非用户明确确认新的设计方向。

## 设计目标

用户打开应用后应迅速判断“现在最值得推进什么”，并能在情报、策略、投递和四条准备轨道之间安静、持续地工作。体验记忆点来自清晰行动、可信事实和克制空间交互，而不是装饰性背景或夸张动效。

## 应用结构

- 默认首页为“今日重点”。
- 投递记录是独立工作流页面，不承担首页角色。
- 全站使用可收起左侧工作台导航。
- 页面顶部只承担标题、当前上下文和主要操作。
- 深层内容使用真实路由、返回按钮和面包屑；浏览器前进、后退和刷新应保持正确页面层级。

### 左侧导航

- 顶部固定入口：今日重点。
- 当前目标画像以简洁上下文卡展示，点击进入独立画像页。
- 工作流：面试情报、准备策略、投递记录。
- 准备轨道：知识、算法、项目、实习。
- 工具：导出、AI 设置。
- 底部显示数据环境和导航收起按钮。
- 展开宽度约 240px；收起后约 68–72px，只保留图标，并通过 hover 与 focus 显示名称。
- 导航文字约 15px，不用缩小字号换取空间。

## 视觉语言

- 气质：安静、温暖的研究工作台。
- 背景使用暖灰，内容面使用米白，正文使用深墨，主要强调使用低饱和墨绿。
- 移除全局网格、条纹、颗粒、渐变、装饰性英文编号和高饱和色块。
- 中文无衬线字体承担正文；衬线字体只少量用于标题。
- 不使用海报式巨型口号，通过留白、字号、字重和细分隔线建立层级。
- 阴影主要用于抽屉、弹窗等浮层，普通卡片不依赖重阴影。
- 状态不能只靠颜色表达，必须同时使用文字、图标或形状线索。

## 字号与密度

- 正文约 16px，行高 1.6–1.7。
- 导航和按钮约 15px。
- 标签与卡片摘要不低于 14px。
- 只有日期、ID、来源等辅助信息使用 12–13px。
- 页面标题约 28–32px；模块标题 20–24px；卡片标题 16–18px。
- 不通过压缩字号解决 1024px 桌面宽度下的布局问题。

## 信息层级

全站遵循“概览 → 操作 → 详情”：

- 首屏只保留当前模块主要状态和首要操作。
- 核心操作始终可见；历史、证据、筛选和技术细节按需展开。
- 深层阅读和长编辑进入独立页面。
- 抽屉只用于不离开上下文的快速预览、简单编辑或状态推进。
- 弹窗只用于短新建、确认和少字段设置。
- 折叠用于次要但仍属于当前页面的辅助内容。
- Tooltip 只解释短术语；多行辅助内容使用 Popover。
- hover 只能增强体验，不能成为关键操作的唯一入口；必须有 focus 和键盘等价路径。

## 页面高度与滚动

- 不使用固定 `100vh` 强行堆叠多个大模块。
- 每个一级页面首屏应形成完整工作单元，避免下一模块只露出标题或半张卡片。
- 长内容自然滚动，不为填满屏幕拉伸卡片或表单。
- 只有连续的一级工作段可使用轻度 `scroll-snap-type: y proximity`；卡片、表单和详情子区不吸附。
- 只有存在真实任务顺序时才提供“下一重点”定位，不把跳转按钮当作布局补丁。

## 表单与反馈

- 默认页面保持阅读状态，不常驻展示大量输入框。
- 简短新建使用弹窗；项目、实习等长表单使用独立新建/编辑页。
- 详情通过明确“编辑”操作进入编辑状态。
- 长表单使用显式保存/取消；离开未保存页面时提醒。
- 单字段状态可局部更新，并立即显示成功或失败反馈。
- 首次加载使用接近最终轮廓的骨架；局部刷新保留原内容。
- 空状态解释原因，并只提供一个最合理的下一步。
- 删除、覆盖确认版本等高风险操作二次确认；普通状态切换不滥用确认弹窗。

## 核心页面职责

### 今日重点

- 首屏突出一个明确的首要行动、原因、关键日期和生成事实。
- 次级区域只展示少量候选行动、临近节点和四轨道摘要。
- 没有可恢复策略快照时如实说明，并引导用户进入策略页主动生成；不得编造任务、实时状态或定时能力。

### 目标画像

- 独立页面展示目标岗位、地点、重点方向和摘要。
- 使用显式编辑模式，不包装成虚假评分。

### 面试情报

- 首页是状态摘要、提交入口、筛选和原始事实列表，不连续平铺提交、详情、检索和规范题多个大板块。
- URL/正文提交是短任务，可使用集中弹窗。
- 单条详情承载来源、处理状态、失败恢复、原文预览、抽取块、个人备注和证据链。
- 检索与规范题是二级页面，保留人工合并、拆分、映射和原文回链。

### 准备策略

- 首要操作是用户主动生成一次规则快照。
- 清楚展示模式、日期、目标画像、生成时间和稳定顺序。
- 建议优先；排序契约、输入摘要、警告和证据解释按需展开。
- 不自动请求、不轮询、不伪造持久化结果。

### 投递记录

- 使用“阶段概要 + 舒适列表 + 快速详情抽屉”，不恢复横向五列看板。
- 列表重点展示公司、岗位、阶段、关键日期和下一步行动。
- 阶段概要用于筛选和分布观察；快速推进可在抽屉完成。
- 复杂内容进入独立详情或编辑页，并支持按 ID 深链恢复。

### 四条准备轨道

- 知识：题目、知识点、口述练习、追问、资料和证据。
- 算法：优先题单、外部练习入口、状态、卡点和复盘。
- 项目：事实证据包、表达版本、追问树和岗位考点关联。
- 实习：职责边界、STAR、量化结果、证据、材料和表达。
- 四轨道共享设计变量和反馈方式，但不强套相同卡片模板或统一评分。

### 导出与 AI 设置

- 导出页保持单一任务：选择范围与格式、生成快照、查看摘要/警告、下载文件。schema 与详细计数默认折叠。
- AI 设置明确区分 Prompt 配置、运行状态、诊断和 token/trace 账本；不扩展为聊天入口或重型后台。

## 桌面布局

- 主内容区流式伸缩，最大宽度约 1280–1360px，并居中显示。
- 常规页面水平留白约 32–48px；长文本详情使用更窄阅读列。
- 约 1024px 宽度下导航可默认收起，但仍使用同一侧栏，不开发移动端专属导航。
- 约 1024×768 和 1440×900 下不应出现整页横向滚动，关键文字不得低于既定字号。
- 宽屏优先增加留白或辅助区域，不无限拉长正文和表单。

## 禁止回归

- 不恢复全局网格、条纹、颗粒、渐变、海报式大标题或普遍小字号。
- 不把所有信息重新连续平铺到一级页面。
- 不让 hover 成为唯一可发现或可执行路径。
- 不用抽屉承载所有深层内容，不用弹窗承载长表单。
- 不为了视觉统一改变情报证据、用户修订、项目/实习事实或 AI 边界。
- 不新增旧版兼容、双版本、功能开关或长期迁移层。
- 不扩展移动端专属能力、通用聊天、定时推送或新业务模块。

当前实现与未验证边界见 `docs/tech-architecture/implementation/frontend-workbench.md` 和 `docs/maintenance/known-issues.md`。
