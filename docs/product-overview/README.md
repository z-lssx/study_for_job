# 产品定位

## 目标
把秋招准备从“零散找资料”变成“目标驱动的准备闭环”。

## 核心原则
- 不做重复内容站
- 公共信息优先，公司差异化只保留少量权重
- 用户自己维护投递记录，交互尽量轻
- AI 负责提炼、归类、总结和表达，规则负责统计、约束和基础优先级
- 所有情报结论尽量回链原始面经证据
- 管理端只保留关键提示词配置和 token 统计

## 模块关系

五个原始模块并非平级，应组织为“面试情报层 -> 策略层 -> 四条准备轨道”。

### 面试情报层

面经是类似历年试卷集的全局输入：

- 持久化保存原始面经和来源
- 抽取规范化题目、技能主题、轮次和追问
- 统计近期高频题和岗位共性
- 提炼少量公司差异
- 为每个结论保留原文证据

它不只服务面经阅读页，还为计划、八股、算法、项目和实习提供需求信号。

### 策略层

- 目标岗位/公司管理
- 投递记录看板
- 综合面经需求和个人掌握度计算优先级；投递阶段只作为临近面试时的弱信号
- 公共岗位画像为主，公司个性化为辅
- 按需生成每日、每周和面试前冲刺任务，由用户在页面主动触发，不做定时自动生成

### 四条准备轨道

- 八股：知识地图、外部资料索引、掌握度、追问训练
- 算法：外部平台题单、刷题记录、错题回炉
- 项目：事实证据、岗位匹配、表达版本、追问模拟
- 实习：事实证据、STAR、量化表达、追问模拟

八股和算法解决知识与技能问题；项目和实习解决个人证据与表达问题，不强行使用相同的数据模型和交互。

## 管理端范围
- 关键场景 prompt 模板配置
- 参数配置
- 片段拼装
- token 使用统计

管理端属于 MVP 范围，但只服务单用户的关键配置和用量观察，不扩展为通用运营后台。

不做：
- 发布回滚
- 多用户权限体系
- 重型运维能力
